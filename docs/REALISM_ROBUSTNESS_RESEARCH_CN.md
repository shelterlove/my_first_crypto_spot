# 回测真实性与稳健性研究

## 2026-07-10 研究批次

### 目标

完成策略研究优先级一和二：先让执行成本与风险进入回测路径，再检查年份、币种、BTC regime、
gross区间、权重和参数扰动的稳健性。所有功能默认关闭，没有修改正式V1策略和testnet参数。

运行：

```bash
python scripts/research_realism_robustness.py
```

输出目录：`results/research/realism_robustness/`。目录包含 `summary.csv`、逐年收益、最差滚动
窗口、币种指标、regime归因、gross归因、权重敏感性和manifest。

## 真实性模型

- 历史USD-M funding按UTC日聚合，每天从现金扣除或返还，并影响以后仓位和复利路径。
- 常规场景增加5bps单边滑点；压力场景10bps。
- 压力场景只成交计划数量的95%。
- target gross cap为2.0；开盘actual gross超过2.2时减到2.0。
- 使用日K low检查盘中强平，maintenance margin rate暂按小名义仓位0.5%假设。
- 强平成交额外使用1%价格折损。
- next-open、原0.1% fee和fixed borrow APR proxy保留。
- Executor已增加 `/fapi/v1/leverageBracket` 鉴权查询；拿到testnet key后必须用实际bracket替换0.5%假设。

限制：OHLC无法知道日内价格路径与8小时funding结算先后；开盘gross减仓也不能防止当天盘中gross因
权益下降再次上升。因此这是比旧回测更严格的日级近似，不是逐笔交易所仿真。

## Regime与Gross归因

- 两币种绝大部分正log-return来自 `STRONG_BULL`。
- ETH在BEAR、普通BULL和RANGE均为负贡献；BNB仅普通BULL略为正贡献。
- RANGE是最弱阶段：A下ETH日均约-0.764%，BNB约-0.533%。
- A中1.5-2.0x bucket风险调整收益较好；超过2x样本很少。
- B中超过2x的ETH/BNB分别只有75/69个样本日，表现较强但存在明显条件选择和小样本偏差，
  不能据此继续提高hard cap。

Regime和gross日期是不连续样本，报告使用平均日收益、胜率、累计log-return和Sharpe；禁止把这些
日期拼接后计算CAGR。脚本已为此增加专门统计函数和回归测试。

## 风险控制发现

- A触发2次开盘hard-gross减仓，B触发7次。
- 所有场景均未触发日K low强平，但这不等于3x isolated安全。
- B虽然target cap为2.0、开盘hard cap为2.2，BNB盘中/收盘gross仍达到2.839x。
- 仅靠日频executor无法把2.2称为全天hard cap；真正的hard cap需要交易所侧条件减仓或更低目标缓冲。
- BTC reference延迟敏感，3日延迟使B年化下降约21.4个百分点并显著扩大最差窗口。

## 决策

1. A继续作为V1研究基线；B不晋升正式策略。
2. 不继续研究trend 2.1及以上。
3. testnet仍保持2x exchange / 1.25x target / 1.50x hard gross。
4. 下一项有效优化不是增加杠杆，而是减少RANGE负贡献，同时保持STRONG_BULL参与度。
5. 拿到testnet key后记录真实maintenance bracket、实际强平距离、funding income和滑点，再校准研究假设。

后续融资仓位门控研究见 `docs/FINANCING_GATE_RESEARCH_CN.md`。90% funding分位门控改善全窗口与
压力场景风险效率，但未通过去2021和预设Sharpe门槛，因此只保留为shadow候选。
